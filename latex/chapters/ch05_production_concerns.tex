\subsection{Observability and cost}
In Production Concerns, the section on Observability and cost examines how engineering teams move from prototype prompts to auditable agent runtimes. We emphasize modular boundaries between research, planning, authoring, review, and build stages. Each stage emits structured JSON so downstream tools can validate contracts before LaTeX assembly. This mirrors production observability: every handoff is logged, versioned, and replayable. \cite{crewai2024} \cite{langgraph2024} \cite{mcp2024}

Our team analysis connects Exercise 02's multiprocess debate orchestrator with this Exercise 03 CrewAI publishing crew. IPC queues enforced mediation between debaters; here sequential tasks enforce editorial roles. Both designs reject uncontrolled agent-to-agent messaging. The Ex02 Parent agent parallels our LaTeX Editor gate: quality checks precede final output. \cite{crewai2024} \cite{langgraph2024} \cite{mcp2024}

Framework choice should begin with the problem shape, not the vendor logo. Linear chains fit deterministic ETL-style flows. Graphs fit stateful approvals. Role crews fit human-organizational metaphors with clear ownership. Cost, latency, privacy, and audit requirements then constrain hosting and model choice. \cite{crewai2024} \cite{langgraph2024} \cite{mcp2024}

Additional detail for Observability and cost: operational maturity requires tests, gatekeeper budgets, structured artifacts, and compile-time validation. Agents must not silently bypass failing LaTeX builds or missing citations. \cite{crewai2024} \cite{langgraph2024} \cite{mcp2024}
